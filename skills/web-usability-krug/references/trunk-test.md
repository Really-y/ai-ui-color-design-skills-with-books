# Trunk test and page/navigation audit checklists

Checklists for auditing a page, a navigation system, a Home page, a mobile screen, or a site's courtesy. Each item cites its chapter in *Don't Make Me Think, Revisited*. Use them after a hands-on pass (try the real tasks first — Intro, playbook §1).

## 1. The trunk test (ch. 6)

Premise: users are "abducted" — they arrive on a deep page from a search engine, a social link or an email, having never seen your navigation. Imagine being blindfolded, driven around in a trunk, and dumped on a random page. When your vision clears (still blurry), you must answer these without hesitation:

| # | Question | Element to find |
|---|---|---|
| 1 | What site is this? | Site ID |
| 2 | What page am I on? | Page name |
| 3 | What are the major sections of this site? | Sections (primary navigation) |
| 4 | What are my options at this level? | Local navigation |
| 5 | Where am I in the scheme of things? | "You are here" indicator(s) |
| 6 | How can I search? | Search |

**Procedure**
1. Choose a page anywhere in the site at random, and print it (or screenshot it).
2. Hold it at arm's length or squint so you can't study it closely. The standard is that these elements pop off the page from overall appearance alone, not from close reading.
3. As quickly as possible, find and circle: Site ID; Page name; Sections (primary navigation); Local navigation; "You are here" indicator(s); Search.
4. Score each: found instantly / found with effort / not found.
5. Repeat on your own site, then ask friends (or test participants) to try it. Expect surprises.

**Pass criteria per element**
- Site ID: top of page (usually upper-left), looks like a logo, visible on every page, links Home.
- Page name: present (nav highlighting is not a substitute), frames the page's unique content, usually the largest text on the page, matches the words of the link that led here.
- Sections: visible as navigation, same place and look as on other pages.
- Local navigation: the subsection options at this level are visible and distinguishable from primary navigation.
- "You are here": current section *and* subsection marked, with at least two visual distinctions (e.g., color + bold); not subtle.
- Search: a box with a button labeled "Search"/"Go" or a magnifying glass; present on every page (unless the site is tiny and well organized).

## 2. Billboard checklist: any page (ch. 1–5)

**First law**
- [ ] A neighbor with no interest in the subject could say "Oh, it's a ____" (ch. 1)
- [ ] No question marks: where am I, where do I begin, where is ___, what's most important, why is it called that, is that an ad? (ch. 1)
- [ ] Nothing cute, marketing-driven, internal or technical in the names of sections, links and buttons (ch. 1)
- [ ] If something can't be self-evident, it is self-explanatory with minimal, carefully crafted text (ch. 1)

**Conventions and hierarchy**
- [ ] Logo top-left; primary navigation across the top or down the left; standard icons for search, video, sharing; genre conventions respected (ch. 3)
- [ ] Any departure from a convention is either as clear as the convention or clearly more valuable (ch. 3)
- [ ] The most important element is the most prominent (size, weight, color, white space, position) (ch. 3)
- [ ] Related things are grouped; headings span only what belongs to them; nesting is visible (ch. 3)
- [ ] Squinting, you can point to and name each area ("navigation," "things I can do," "stuff for sale," "promos") (ch. 3)

**Clickability and noise**
- [ ] Every clickable thing has a cue (shape, location or formatting); one color for text links; headings never share the link color (ch. 3)
- [ ] No shouting: no competing exclamation points, typefaces, bright colors, auto-slideshows, animations, pop-ups (ch. 3)
- [ ] Elements align to a grid; no "ransacked room" (ch. 3)
- [ ] Nothing on the page survives "presumed guilty until proven innocent" without a real contribution (ch. 3)

**Text**
- [ ] Plenty of headings; levels visibly distinct; no floating headings (closer to the text below) (ch. 3, 13)
- [ ] Short paragraphs; lists for any series; a little space between list items; sparing bold on key terms (ch. 3)
- [ ] Could you cut half the words? Then half again? (ch. 5)
- [ ] No happy talk ("Welcome to...", "how great we are"); no section-front intros that just restate the links (ch. 5)
- [ ] No instructions, or the bare minimum (ch. 5)

**Choices**
- [ ] Each click on the page is a mindless, unambiguous choice with strong scent (ch. 4)
- [ ] Any unavoidable hard choice has guidance that is brief, timely and unavoidable (ch. 4)

**Definitive rules**
- [ ] No small, low-contrast type (ch. 13)
- [ ] Visited and unvisited links look noticeably different (ch. 13)

## 3. Navigation system checklist (ch. 6)

- [ ] Persistent navigation appears on every page in the same place with the same look (forms excepted)
- [ ] It contains: Site ID, Sections, Utilities, Search, a way Home
- [ ] Form pages (checkout, registration, subscribe, feedback, preferences) show only Site ID, Home and form-helping utilities
- [ ] Site ID: top, usually upper-left; distinctive typeface and graphic recognizable at any size; links Home; "Home" also appears among sections
- [ ] Sections = the real top level of the hierarchy; secondary navigation placement decided (persistent area / dropdown / section front)
- [ ] Utilities: ≤ 4–5 in the persistent nav, slightly less prominent than Sections; the rest in the footer
- [ ] Search: box + button + "Search" (or magnifying glass); button "Go" if box says "Search"; no Find/Quick Search; no "type a keyword"; no up-front scope/field options; scope only where confusion is possible; scoping offered on results pages
- [ ] Sample pages exist and are consistent for every level (Home, section front, level 2, level 3, deepest) — lower levels aren't ad hoc
- [ ] Every page has a page name: framing the unique content, prominent (usually largest text), matching the clicked link (or close with an obvious reason, e.g., "Gifts for Him" → "Gifts for Men")
- [ ] "You are here" marked at every level in every nav structure on the page, with ≥ 2 distinctions; a designer thinks it sticks out — good
- [ ] Breadcrumbs (large/deep sites): at the top; `>` separators; last item bold and unlinked
- [ ] Tabs (if used): active tab contrasting color and physically connected to the content area
- [ ] Trunk test passes on three random deep pages
- [ ] Navigation reveals what's here (hierarchy visible), tells where to begin and what the options are, and looks competent

## 4. Home page checklist (ch. 7)

**Big picture (first casualty — check first)**
- [ ] At a glance, correctly and unambiguously: What is this? What can I do here? What do they have here? Why should I be here and not somewhere else?
- [ ] Tagline visually attached to the Site ID: 6–8 words, clear, informative, differentiating (nobody else could use it), benefit-bearing, lively; not a motto, not generic
- [ ] Welcome blurb (if needed): terse, prominent block top-left/center; not a mission statement
- [ ] "Learn more" path (short explanatory video) for novel propositions
- [ ] Explanation uses as much space as needed and no more; mentions a few key features, not all
- [ ] Shown to outsiders who could say what the site is (the one thing insiders won't notice missing)

**Obligations covered**
- [ ] Site identity and mission; hierarchy via persistent nav; prominent search box
- [ ] Teases: content promos (newest/best/popular) and feature promos
- [ ] Timely content or at least signs of life (recent item, press release)
- [ ] Deals/co-branding placed; shortcuts to the most requested items
- [ ] Register / Sign in visible; signed-in state shown ("Welcome back, ___")
- [ ] Credibility and trust established

**Fifth question — where do I start?**
- [ ] Obvious where to start to search, to browse, to sample the best stuff
- [ ] Step-by-step process entry point leaps out; labeled "Start here"
- [ ] Entry points look like entry points (search box looks like a search box; section list looks like a list) and are labeled "Search," "Browse by Category," "Sign in"
- [ ] Promos don't yell over the entry points

**Commons**
- [ ] Every promo justified against the shared cost of clutter; rotation or cross-promotion from popular pages used instead of "one more thing"
- [ ] Above-the-fold content prioritized for what users scan for, not for who shouted loudest

**Deep pages**
- [ ] Deep pages also orient (Site ID + tagline, page name, sections) since most visitors don't enter via Home; Home is where they "bob up" to get bearings

## 5. Form / choice checklist (ch. 4, 11, 13)

- [ ] Each question is answerable without self-classification into your segments; staged into simple first pick → relevant details
- [ ] Help is brief, timely, unavoidable and adjacent to the field; no hover-only help on touch
- [ ] Accepts any reasonable formatting (spaces, dashes, parentheses)
- [ ] Asks only what the task needs; no giant registration form
- [ ] Labels outside fields (or all five in-field conditions met); `<label>` elements used
- [ ] Persistent navigation minimized on the form page
- [ ] Clear, graceful error recovery
- [ ] Price, shipping, fees shown before commitment

## 6. Mobile screen checklist (ch. 10)

- [ ] Frequent/hurried actions one tap away; everything else on an obvious path; depth acceptable if scent holds at every tap
- [ ] No feature cut on the assumption that mobile users are "on the move"
- [ ] Every tappable element has visible affordances; inputs have borders; flat styling compensated with ≥ 2 remaining dimensions (position, reversed type, caps, color, shape)
- [ ] Nothing depends on hover (tooltips, menus, hover highlights)
- [ ] Zooming allowed
- [ ] Links from email/social open the content, not the mobile Home page
- [ ] Mobile Site / Full Site toggle at the bottom of every page
- [ ] Assets sized for the screen; tested on cellular, not just Wi-Fi; the tapped item shows before the rest loads
- [ ] Apps: tour/help findable later; level structure visible; Help reachable when stuck; primary task completable after the tutorial; controls memorable (not gesture-only secrets)
- [ ] Delight pursued only after learnable/effective/efficient are secured
- [ ] Tradeoffs documented: for each annoying behavior, the constraint it serves and the user cost

## 7. Courtesy checklist (ch. 11)

- [ ] The three main things users come to do are obvious, easy, unobstructed
- [ ] Support phone number, shipping rates, prices and fees in plain sight
- [ ] No data-format punishment; no unnecessary personal information
- [ ] No faux sincerity ("Your call is important to us"); no marketing sizzle blocking the path
- [ ] Looks professional and organized
- [ ] Candid about bad news (outages, fees, strikes); the one question everyone is asking is answered on Home
- [ ] Steps saved where possible (prefilled tracking links)
- [ ] Support content shows effort: accurate, clear, organized, findable
- [ ] FAQs are real (not QWWPWAs), current (this week's top five first), candid
- [ ] Printer-friendly pages (ads dropped, figures kept)
- [ ] Errors recoverable gracefully; apologies where you can't help
- [ ] Any deliberate annoyance (pop-ups) is an informed business decision

## 8. Accessibility quick checklist (ch. 12–13)

- [ ] Everything that confuses everyone is fixed first (tested)
- [ ] Text Size increase in the browser actually enlarges text
- [ ] `alt` on every image (`alt=""` for decorative)
- [ ] Headings in semantic order (h1 → h2 → h3), styled by CSS
- [ ] `<label>` for every field
- [ ] "Skip to Main Content" link at the top of every page
- [ ] Full keyboard access
- [ ] Strong contrast; never light grey on dark grey; no small low-contrast type
- [ ] Keywords at the start of links and lines (screen-reader users scan with their ears)
- [ ] Accessible template/theme

## 9. Scoring and reporting

- Report findings as **observed or predicted question marks**, each with: element, the question the user would ask, the cause category (name / clickability / hierarchy / noise / words / choice / navigation element / big picture / goodwill / accessibility), the chapter rule it breaks, and the least-you-can-do fix.
- Rank by seriousness for the main tasks (would most users fail or give up?), not by effort. Flag kayak problems separately and leave them.
- Mark anything you're guessing about as "verify with 3 users" and attach the task you'd give them (`usability-test-kit.md`).
- Prefer a live walkthrough with the team to a "big honking report" (Intro).
